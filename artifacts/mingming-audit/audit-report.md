# 鸣鸣很忙案例页：布局与交互审计

日期：2026-08-31

## 审计范围

- 页面：`/cases/mingming`
- 用户目标：在前 5 秒理解角色、AI 长视频主线、IP 孵化成果与 Agent 能力，并能稳定浏览章节、证据和后续入口。
- 视口：1440×900、1280×800、1024×768、390×844、375×812。
- 证据：本目录中的 3 张真实应用内浏览器截图，以及浏览器 DOM、URL、滚动位置与控制台读数。

## 流程步骤与健康度

1. **详情首屏 — 健康**  
   `CASE 01 / IP 制作人`、鸣鸣很忙、AI 长视频定位句与 3 个核心成果同屏；首屏只有一个主叙事。
2. **AI 长视频章节 — 健康**  
   两支 16:9 视频先于角色、流程和过程证据；桌面媒体约 8 列、文案约 4 列，移动端顺序为项目名 → 视频 → 3 条要点。
3. **IP 孵化章节 — 健康**  
   20+ 为唯一最大成果；业务路径只有 A–D 四条；默认展示 6 个账号、6 张培训图，移动端各 4 个。
4. **Agent 章节 — 健康**  
   4 阶段工作流、3 张真实截图优先，待补资料默认收起；章节高度短于 AI 主章节。
5. **返回与深链 — 健康**  
   首页进入、浏览器后退/前进、直接访问详情的 fallback、章节刷新、重复 hash 点击均按预期工作，无旧页或首页闪帧。

## UX 与视觉结论

### 已确认优势

- 信息权重形成明确的 `AI 视频 > IP 孵化 > Agent` 顺序。
- Hero 的定位、职责和结果不再互相争夺注意力。
- 原 7 步制作过程压缩为 4 阶段，同时保留次级步骤名称。
- 账号墙、培训、过程证据、复盘占位和 Agent 占位使用原生 `details/summary` 渐进披露。
- 真实截图总是排在占位资料之前；占位使用虚线和更低对比度。
- 桌面与移动端均无横向溢出，Logo 在移动端为 56px 且不覆盖返回按钮。

### 可访问性确认

- 展开控件使用原生 `details/summary`，无需自制键盘状态机。
- 路由链接保留新标签、修饰键和浏览器历史语义。
- 章节深链会把目标移入视口并聚焦目标；详情首屏保留可见返回入口。
- `prefers-reduced-motion` 规则继续生效。

### 证据限制

- 截图不能单独证明完整 WCAG 合规；本次同时检查了语义控件、焦点路由、视口重排与控制台。
- 两支视频尚无真实 MP4、封面和字幕，播放器视觉只能验证尺寸、顺序和占位状态。

## 素材补齐优先级

1. **P0：两支 AI 长视频** — 浙江、石家庄 MP4；各自 1920×1080 封面；字幕 VTT。
2. **P1：三类制作证据** — Brief、文案/脚本、剪辑时间线，建议 1600×1000。
3. **P2：协作与复盘** — 另一位成员分工、AIGC/分镜过程、成片复盘数据。
4. **P3：扩展业务证据** — 视频号代表视频/截图/数据，高管 IP 定位说明，Agent 协作过程与核心代码截图。
