# 作品网站性能优化与保真验收

## 范围与基线

本轮基线：`d9ba0341b3843cab9ec4b39cd0e29c56318f5823`。

目标是减少首屏等待、不可见动画空跑和渲染重复工作，不改变视觉方向、文案、图片清晰度、3D 轨道参数或详情交互。没有新增依赖，没有改动图片、视频、字体、案例数据或兴趣数据。保留了用户原有的 `src/styles/mingming-hierarchy.css` 和 `vite.config.js` 工作区修改，未纳入本轮提交。

## 真实问题与修复

1. **首页原来只有空 root，须等待 JS 下载、执行才能出现首屏。** 构建时由现有 React 组件生成相同的静态首页，浏览器收到 HTML 即可发现肖像并呈现内容，之后 React hydration 接管。仍为静态站点，不需要新的服务器。时钟在接管前按当前时间同步；锚点导航标记也同步。详情直达和 reduced-motion 使用原来的客户端渲染。时间种子仅供首次接管，后续返回首页使用当前时间；以 transition 释放种子，避免更新未完成 hydration 的 Suspense。
2. **画廊虽透明、尚未出现，却持续更新轨道。** 原 `useAnimationFrame` 常驻回调替换为仅在可见且原有入场透明度大于零时注册的帧更新，退出后取消。原速度、淡入、滚动弹簧和图片编排不变。
3. **关于我的逐字效果有大量独立订阅。** 保留 206 字和原来的三层字符 DOM、排版、偏移与透明度曲线，改为每段一个靠近视口时的订阅；离开视口取消，重复相同透明度不写 DOM。
4. **首屏提前创建 WebGL 探测上下文。** 在靠近工具区时才检测，及时释放探测用 GPU 上下文；真正 3D 的分辨率、轨道、光影、速度和手机能力不变。
5. **3D 生产环境仍逐帧写调试 JSON，聚焦结束还重复写完成态面板。** 调试投影与 DOM 数据仅在诊断模式运行；保留实际遮挡投影和着色器更新。完成态面板停止重复写入。回缩使用当前 Three 视口尺寸，避免每帧读取 DOM 布局，也兼容窗口调整。
6. **画廊每张卡片内外层长期声明 will-change。** 保留实际 3D 变换与阴影，仅在正在悬停时给内层卡片声明提示，保留移动轨道的合成提示。
7. **部分详情照片依赖浏览器默认懒加载，快滚时请求偏晚。** 对当前详情容器里已有的 `img[loading="lazy"][src]` 使用一个 IntersectionObserver，在距视口 2000px 时改为 eager，提前下载；触发后取消观察，离页断开。没有提高 fetchPriority、修改原图、src 或 srcset；不一次请求整页，也不干预 ViewportImage 和动态折叠证据原有加载器。

## 性能测量

同机、同浏览器、1440×900、约 120Hz，生产构建各记录 10 秒。审计代码只存在于独立本地审计构建；正式产物不含审计按钮、帧包装器或审计模块。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首屏静止时应用帧回调 | 1200 | 0 |
| 首屏应用帧回调累计时间 | 127.4ms | 0ms |
| 工具星系应用帧回调（最终同环境复测） | 2394 | 1198 |
| 工具星系回调累计时间（最终同环境复测） | 519.3ms | 519.1ms |
| 工具星系帧间隔 P95（最终同环境复测） | 8.4ms | 8.4ms |
| 10 秒中超过 32ms 的帧（最终同环境复测） | 0 | 0 |

这是本机采样，不是全球速度、CPU 百分比或 GPU 利用率。优化前本机 3D 也没有掉帧，因此不把减少回调数宣传成帧率翻倍。首屏静态化减少对 JS 完成的依赖，不等于消除网络响应、字体或图片传输等待。

保留采样波动：优化版本前一次记录为 937 次回调、P95 16.8ms、1 次超过 32ms，随后同环境基线/优化复测为上表。不能用单次采样断言所有设备不会掉帧；减少的主要是不可见画廊回调，3D 本身依然需要渲染。

## 后续边界

正式站仍使用现有 EdgeOne 线路，视频仍在腾讯云香港 COS。这次没有购买服务、更换 CDN 地区、DNS 或视频文件。不同运营商、跨境线路、第一次访问缓存以及大型视频传输仍可能影响体验，不能由代码验收证明“所有人的任何网络都秒开”。

保留的明确成本：3D 的 Three/Fiber/Drei 运行时仍需首次下载（约 242.59KB gzip）；旅行 13 张原图共约 4.9MB，浙江原图约 1.38MB。这次以原图清晰度和原效果不变为约束，不通过降低分辨率或移除 3D 换取速度。鸣鸣很忙案例原有开场有 1600ms 展示加 650ms 揭幕、2300ms 结束计时，仍保留；这段主动等待不等同于网络卡顿。

审计复测方法：`node scripts/build-audit.mjs <明确的绝对输出目录>`，再执行 `node scripts/prerender-home.mjs <同一目录>`；通过 Vite preview 打开该目录，加 `?perf-audit=1` 后手动录制。不要把审计目录部署到正式站。
